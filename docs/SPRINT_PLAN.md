# AMUR.BG — План работ агента (4 подхода)

> Этот документ — рабочая карта для ИИ-агента. Каждый «подход» = один
> самодостаточный спринт: завершается зелёным билдом (`npm run build`,
> 0 TS-ошибок) и коммитом+пушем в ветку `claude/amur-mvp-v2-analysis-2yU41`.
> Порядок строго по приоритету: ВЫСОКИЙ → СРЕДНИЙ → НИЗКИЙ.

Текущая база: 14 routes, 2 миграции, Sprint 1–3 завершены.

---

## 🔴 ПОДХОД 1 — Безопасность и данные (БЛОКЕРЫ ЗАПУСКА)

**Цель:** закрыть критические дыры, без которых нельзя пускать реальных клиентов.

### Задачи
1. **Auth на `/admin` и `/hub`** (GDPR-блокер — сейчас ПД открыты всем)
   - `@supabase/ssr` + middleware `middleware.ts` для защиты роутов
   - Страница `/login` (Supabase Auth, email+пароль или magic link)
   - Роли: `admin` (полный доступ), `florist` (только свой хаб)
   - Редирект неавторизованных на `/login`
2. **Каталог из БД** (сейчас 6 букетов захардкожены)
   - `/` и `/checkout` читают `products` из Supabase, а не из `CATALOG` константы
   - Server Component с `getSupabaseClient()` на витрине
   - Фолбэк-состояние «нет товаров»
3. **Seed реальных товаров** → `supabase/migrations/03_products_seed.sql`

### Definition of Done
- [ ] `/admin` и `/hub` редиректят на `/login` без сессии
- [ ] Витрина и checkout берут товары из БД
- [ ] `npm run build` зелёный, коммит+пуш

## 🔴 ПОДХОД 2 — Фото-пруф и корзина (ЯДРО ЦЕННОСТИ)

**Цель:** довести до конца главный moat — фото вручения — и снять
ограничение «1 товар = 1 заказ».

### Задачи
1. **Supabase Storage для фото вручения**
   - Bucket `delivery-proofs` (private) + RLS-политика
   - `lib/storage.ts` — `uploadDeliveryPhoto()`
   - В `/hub` — кнопка/инпут загрузки фото курьером → `POST /api/orders/[id]/photo`
   - После загрузки: статус `delivered` + URL в `photo_proof_url`
2. **Фото-отчёт клиенту** (закрывает страх «а вручат ли нормально»)
   - При загрузке фото → Viber/SMS клиенту со снимком
   - `buildCustomerPhotoNotice()` в `lib/viber.ts`
3. **Корзина / мультитоварные заказы**
   - `lib/cart.ts` (localStorage или Zustand) — add/remove/qty
   - `/checkout` шлёт массив `items[]` (API уже это принимает!)
   - Пересчёт суммы + повторная валидация нечётности по всей корзине

### Definition of Done
- [ ] Курьер грузит фото из `/hub`, оно сохраняется в Storage
- [ ] Клиент получает фото-отчёт
- [ ] Можно заказать несколько букетов в одном чеке
- [ ] Билд зелёный, коммит+пуш

## 🟡 ПОДХОД 3 — Платежи, зоны, обратная связь (SOFT LAUNCH)

**Цель:** поднять конверсию и включить сбор фидбека по плану из MVP-доку.

### Задачи
1. **Apple Pay / Google Pay** — добавить в Stripe Checkout
   - `payment_method_types: ["card"]` уже включает кошельки при HTTPS-домене;
     проверить + автоматический wallet-рендер
2. **Зоны доставки по хабам** (логика в `lib/constants.ts` есть, не подключена)
   - Геокодинг определяет ближайший хаб → его `feeEur`
   - `delivery_fee` динамический, не фикс 5 €
   - Назначение `hub_id` заказу по зоне
3. **NPS-опрос после доставки** — «Оцените вручение 1–5» в Viber
   - Таблица `order_feedback` (миграция 04)
   - Бот ловит ответ 1–5 → пишет в БД
   - Вывод среднего NPS в `/admin`
4. **Email-уведомления** (резерв к Viber/SMS) — Resend или Supabase SMTP

### Definition of Done
- [ ] Кошельки видны в Stripe Checkout
- [ ] Доставка считается по зоне/хабу
- [ ] NPS собирается и виден в админке
- [ ] Билд зелёный, коммит+пуш

## 🟡🟢 ПОДХОД 4 — Метрики, изображения, надёжность (ПОЛИРОВКА)

**Цель:** дать владельцу цифры для решений и убрать визуальные/тех. долги.

### Задачи
1. **Дашборд метрик в `/admin`**
   - Конверсия корзины, % COD vs карта, % заказов <2ч (SLA), повторные за 60 дней
   - Supabase views/RPC для агрегатов (не тянуть всё в браузер)
2. **Загрузка изображений товаров** (сейчас `✿` placeholder)
   - Bucket `product-images`, поле `image_url` уже в схеме
   - Аплоад из админки (форма товара)
3. **Полный календарь именин** — расширить `name_days` из БД БАН (~30 → полный)
4. **Тесты + CI**
   - Vitest на `lib/constants.ts` (нечётность, dual-price), `lib/geo.ts`
   - GitHub Actions: `tsc --noEmit` + `npm run build` на PR
   - SessionStart-хук (skill `session-start-hook`) для веб-сессий
5. **Управление товарами в админке** (CRUD продуктов)

### Definition of Done
- [ ] В админке видны ключевые метрики
- [ ] Товары имеют реальные фото, управляются из админки
- [ ] CI гоняет билд+типы на каждом PR
- [ ] Билд зелёный, коммит+пуш

## Сквозные правила для каждого подхода
- Перед началом: `git pull origin claude/amur-mvp-v2-analysis-2yU41`
- Каждая БД-правка → новая нумерованная миграция в `supabase/migrations/`
- Новые env-переменные → дописать в `.env.example`
- Завершать: `npx tsc --noEmit` && `npm run build` зелёные → commit → push
- НЕ создавать PR без явной просьбы пользователя
- Обновлять чек-боксы Definition of Done в этом файле по мере выполнения
